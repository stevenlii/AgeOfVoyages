# AgeOfVoyages（纵横四海）操作说明

本说明用于**本机构建 / 启动调试**（`deploy/bin/build.sh`），以及**把服务部署到完全离线的机器**（`deploy/bin/build.sh deploy` 生成包 + 离线机 `deploy/bin/deploy.sh` 启动）。

---

## 0. 最小上手示例

```bash
# —— 开发本机 ——
./deploy/bin/build.sh start           # 构建并启动（看 deploy/logs/ 确认端口 OK）
./deploy/bin/build.sh logs            # 看日志
./deploy/bin/build.sh stop            # 关停

# —— 生成离线包 ——
./deploy/bin/build.sh deploy          # 产出 deploy.tar.gz

# —— 离线机器 ——
tar -xzvf deploy.tar.gz && cd deploy-<版本> && ./bin/deploy.sh start
```

- 本机（开发机）需要 **Maven + JDK 21**，`build.sh` 会负责编译前端 + 后端。
- 离线机器**只需要 JDK 21**，`deploy.sh` 直接 `java -jar`，不碰 Maven、不联网。
- 前端（Vue/Vite）构建产物会并入后端 fat-jar（同源托管），离线机无需 Node。

## 1. 环境要求

| 组件 | 本机（跑 `build.sh`） | 离线机器（跑 `deploy.sh`） |
|------|------|------|
| JDK | 21+ | 21+（脚本会检测） |
| Maven | 需要（脚本自动找 `PATH` 或 IDEA 自带） | **不需要** |
| Node/npm | 需要（仅构建前端用） | **不需要** |
| 网络 | 首次构建需联网拉依赖 | **完全不需要** |

## 2. 目录结构

```
AgeOfVoyages/
├── backend/                     Spring Boot 后端（端口 8080，含 WebSocket/STOMP）
│   ├── pom.xml
│   └── src/main/resources/application.yml
├── frontend/                    Vue3 + Vite 前端（dev 端口 5173）
├── deploy/                      部署相关目录
│   ├── bin/
│   │   ├── build.sh            【本机用】构建 + 启动 + 打包离线部署
│   │   └── deploy.sh           【离线机用】启动脚本（无需 Maven）
│   ├── conf/
│   │   ├── deploy.properties   【离线机用】声明“包内文件”与“离线机真实文件”的对应关系
│   │   └── router.properties   服务路由（当前单一服务，占位）
│   ├── config/                 application.yml + env.yml（构建时生成，env.yml 不随包分发）
│   ├── jars/                   fat-jar（deploy 包生成）
│   ├── 部署脚本使用说明.md      本文档
│   └── logs/                   运行时日志与 pid
└── deploy.tar.gz               离线部署压缩包（由 build.sh deploy 生成）
```

> **端口约定**：后端 = **8080**，Web UI `http://127.0.0.1:8080/`，WebSocket `ws://127.0.0.1:8080/ws`。
> 前端开发模式：`cd frontend && npm run dev`，Vite 把 `/ws` 代理到后端 8080。

## 3. `build.sh`（本机使用，位于 `deploy/bin/`）

| 命令 | 作用 |
|------|------|
| `./deploy/bin/build.sh` | 无参数时打印用法说明并退出 |
| `./deploy/bin/build.sh start` | 构建前端（npm build 并入后端 static/）+ 后端（mvn package 打 fat-jar）+ 启动。若检测到服务已在运行，会交互询问 Y/N 是否重启 |
| `./deploy/bin/build.sh stop` | 停止服务 |
| `./deploy/bin/build.sh restart` | 重启（= stop + start） |
| `./deploy/bin/build.sh logs` | 实时跟踪日志 |
| `./deploy/bin/build.sh status` | 查看服务运行状态、pid、运行时长、端口 |
| `./deploy/bin/build.sh deploy` | 构建并打包离线部署包 `deploy/release/deploy-<日期>.tar.gz` |

### 环境变量

| 变量 | 作用 |
|------|------|
| `SKIP_BUILD=1` | 跳过 Maven + 前端构建，直接启动 |
| `SKIP_FRONTEND_BUILD=1` | 跳过前端 npm 构建 |
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | 覆盖后端数据库连接 |

## 4. 离线部署

### 4.1 为什么单独做离线包

本机 `build.sh` 依赖 Maven 在线拉依赖编译。离线机器连不上仓库，直接在那台机器上 `mvn` 会失败。正确做法是在**能联网的本机**用 `./deploy/bin/build.sh deploy` 把“已编译好、自带全部依赖的 fat-jar”打包，拷到离线机后只做 `java -jar` 启动。

### 4.2 配置 / 密钥替换（deploy.properties）

离线机的**真实密钥与配置**不要写进仓库或部署包，而是放在离线机本地路径，再通过 `deploy/conf/deploy.properties` 让 `deploy.sh start` 启动时复制覆盖到部署包内。

```properties
# 规则（.current 与 .runtime 成对出现）
env.current=config/env.yml
env.runtime=~/Documents/age-of-voyages-config/env.yml
```

`env.yml` 为 YAML 格式，键名与代码里的 `${VAR}` 占位符一致（如 `DB_PASSWORD`）。示例：

```yaml
DB_URL: "jdbc:mysql://host:3306/age_of_voyages?..."
DB_USERNAME: "root"
DB_PASSWORD: "真实密码"
```

> `config/env.yml` **不随 deploy.tar.gz 打包**，由离线机经 `env.runtime` 提供。

### 4.3 离线机器操作步骤

```bash
# 把 deploy.tar.gz 传到离线机
cd ~/Documents/ageofvoyages
tar -xzvf deploy.tar.gz
cd deploy-<版本>

# 启动（离线机只需 JDK 21+）
./bin/deploy.sh start
./bin/deploy.sh status
./bin/deploy.sh logs
./bin/deploy.sh stop
```

## 5. 常见问题

| 现象 | 可能原因 / 处理 |
|------|------|
| 启动后 8080 未就绪 | 看 `deploy/logs/backend.log` |
| `Unknown host maven.aliyun.com` | 在离线机误跑了 Maven 构建，离线机只能用 `deploy.sh` |
| 端口被占用 | 先 `./bin/deploy.sh stop` 再 start，或用 `lsof -ti tcp:8080` 定位占用进程 |
| 数据库连接失败 | 检查 `config/env.yml` 或 `DB_*` 环境变量是否正确 |
| JDK 版本过低 | 脚本检测 <21 会退出，请先安装 JDK 21+ |
