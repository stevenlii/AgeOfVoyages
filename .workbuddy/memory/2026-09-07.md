## 纵横四海 后端由 Node 改为 Java（Spring Boot）

- 用户决定：后端改成 **Java（Spring Boot）**，前端用 **Vue 3**；实时通信走 **WebSocket/STOMP**（不再用 Socket.io）。
- 新建结构：
  - `backend/`（Maven + Spring Boot 3.3.5 + Java 21 + spring-boot-starter-websocket）
    - 端点 `/ws`（SockJS），应用前缀 `/app`，broker `/topic`
    - 玩家状态按 `clientId` 推送：`/topic/player/{clientId}/state`、`/topic/player/{clientId}/msg`；全服广播 `/topic/log`
    - 指令：`/app/login` `/app/travel` `/app/trade` `/app/chat`
    - 内存存储（未落库）；行情每 5 分钟浮动；航行用 ScheduledExecutorService 定时到达
  - `frontend/`（Vite + Vue3 + @stomp/stompjs + sockjs-client），vite 开发代理 `/ws` → 8080
- 验证：Maven `package` 通过；`node smoke-test.mjs` 经 STOMP 跑通 登录→买葡萄酒5(花780)→卖5(得700) 金币闭环；前端 `npm run build` 通过。
- 注意：本机 Maven 默认是 3.6.3（沙箱拦截写仓库），已改用 3.9.16 并 `-Dmaven.repo.local=$HOME/.m2/repository` + 关闭沙箱编译。Java 后端经托管后台启动时曾被分配 58295 端口，已用 `--server.port=8080` 显式指定。
- 已删除被取代的旧 Node MVP 文件（server.js / public / test_client.js / 根 package.json）。

## 接 MySQL 持久化（玩家数据落库）
- 新增 spring-boot-starter-data-jpa + mysql-connector-j；application.yml 配数据源 `jdbc:mysql://localhost:3306/age_of_voyages?createDatabaseIfNotExist=true`（root/REMOVED），`ddl-auto=update`。
- 实体 `PlayerEntity`（client_id 主键，`cargo` 用 `CargoConverter` 存 JSON 文本列）；`PlayerRepository` extends JpaRepository；`DebugController` 提供 `/debug/player/{clientId}` 验证用（标注上线前移除）。
- GameService 注入 PlayerRepository：login 从库 hydrate（含航行到期重启恢复），trade/travel/到达 写回库；实时状态仍在内存 ConcurrentHashMap。
- 验证：smoke-test.mjs 改为固定 clientId，买后 DB=gold230/cargo{wine:5}、卖后 DB=gold925/cargo{}，通过。
- 注意：本机 Maven 必须用 3.9.16 + `-Dmaven.repo.local=$HOME/.m2/repository` + 关闭沙箱；后端由托管后台启动需 `--server.port=8080` 显式锁端口（否则被分配到随机端口）。

## 数据访问层由 JPA 迁移到 MyBatis
- 起因：用户问"后端是 mybatis+mysql+spring 吧"，实际当时是 JPA；用户确认希望统一到 **MyBatis**（与其 mcpdb 项目同栈）。
- 改动：
  - `pom.xml`：`spring-boot-starter-data-jpa` → `mybatis-spring-boot-starter:3.0.4`（保留 mysql-connector-j runtime）。jar 由 48MB 降到 26MB。
  - `PlayerEntity`：去掉 JPA 注解改纯 POJO，**保留 public 字段 + 新增 setter**（MyBatis 结果映射只认 setter，不认 public 字段；保留 public 是为了 GameService 少改）。
  - `CargoConverter`(JPA AttributeConverter) → `CargoTypeHandler extends BaseTypeHandler<Map<String,Integer>>`，配 `@MappedTypes(Map.class)`。
  - `PlayerRepository`(JpaRepository) → `PlayerMapper`(@Mapper)，注解 SQL：`findById`/`insert`/`update`，cargo 参数显式 `typeHandler=...CargoTypeHandler`。
  - 因 MyBatis 无 JPA `save()` 语义，GameService 新增 `persist()`（findById==null 则 insert，否则 update）；`repo.findById().ifPresent()/.orElse()` 改为 null 判断。
  - `application.yml`：删 jpa 段，加**顶层** `mybatis.configuration.map-underscore-to-camel-case=true` + `type-handlers-package`。
  - 新增 `backend/schemas/schema.sql`（MyBatis 不自动建表，换环境需手动执行）。
- 踩坑：
  1. **`mybatis:` 配置必须顶层**，误缩进到 `spring:` 下会导致配置不生效（已修正）。
  2. 本机 `PATH` 无 mysql 客户端，实际路径 `/usr/local/mysql/bin/mysql`。
- 验证：新/老 clientId 各跑一次 smoke-test（`SMOKE_CLIENT_ID` 环境变量控制，已参数化）——已存在玩家登录读出 925（证明 hydrate 生效），全新玩家 1000 起、DB 落 gold=195/cargo{wine:5}（证明 INSERT 生效）；mysql 客户端直查 players 表两行均在。
